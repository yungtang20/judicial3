## 一、測試狀態判定四大標準 (8.1 條)

所有測試案例之結果判定，必須嚴格遵守以下四種狀態，嚴禁模糊標註：

* **`PASS`**：已實際執行驗證，輸出結果完全符合規格預期，且具備可重複檢查之真實日誌證據。
* **`FAIL`**：已實際執行驗證，但輸出結果與規格不符或發生例外中斷。
* **`NOT_RUN`**：因尚未到達該開發階段或尚待配置而尚未執行之測試。
* **`BLOCKED`**：因前置條件缺失（如雲端憑證尚未設定、網路隔離受阻）而無法執行之測試。

> **紅線守則**：嚴禁以程式碼編譯成功、檔案存在或模型口頭聲稱代替真實測試證據！

## 二、測試分層架構 (8.2 條)

1. **單元測試 (Unit Tests)**：
   - 狀態機合法轉移與非法拒絕測試。
   - 條陳公文字數與段落排序檢查器測試。
   - 依賴關係級聯失效（STALE Invalidation）邏輯測試。
   - AES-256-GCM 加密與密文竄改拒絕測試。
2. **整合測試 (Integration Tests)**：
   - API 認證與水平越權防護測試。
   - PostgreSQL 外鍵關聯與 CHECK 約束測試。
   - Gate 0～5 版本連動與審核日誌記錄測試。
3. **法律推理品質測試 (Legal Reasoning Quality Tests)**：
   - 多元罪名候選完整性（Primary、Alternative、Rejected）檢驗。
   - 未知事實保留度與否認陳述不轉移真偽檢驗。
   - 9 大類問句對應待證構成要件檢驗。
4. **安全與復原測試 (Security & Disaster Recovery Tests)**：
   - 外部 AI 關閉時零案件資料封包外流測試。
   - 備份檔於隔離沙盒環境之資料解密與一致性驗證。

## 三、十大固定回歸測試案例 (8.3 條)

| 編號 | 測試場景 | 核心檢驗目標 | 預期判定基準 |
| :--- | :--- | :--- | :--- |
| **TC-01** | 事實明確且無矛盾案例（ATM 車手案） | 候選罪名完整性、要件逐一對齊 | 產製加重詐欺與洗錢罪，正確列出主客觀要件 |
| **TC-02** | 重要事實未知案例（虛擬貨幣假投資） | 未知事實保留（UNKNOWN 非 FALSE） | 保留待查事項，禁止妄斷已獲利或已轉移 |
| **TC-03** | 當事人否認抗辯案例（辯稱不知贓款） | 否認陳述標記（DENIED 非客觀不存在） | 標註主觀否認狀態，產製突破心防之問句 |
| **TC-04** | 證據與陳述互相矛盾案例（監視錄影與自白） | 矛盾衝突標註與追問規劃 | 標記爭點，產製第 8 類「矛盾與補充問句」 |
| **TC-05** | 多重合理法律方向案例（皮夾遺失與盜刷） | 侵占遺失物 vs 竊盜 vs 詐欺併存評估 | 同時並列主位與備位罪名，不得單一罪名偏見 |
| **TC-06** | 同一案件涉及多行為階段（交付/分流/提款） | 各階段行為獨立評價與競合分析 | 分段拆解各行為人之分工與法定刑評價 |
| **TC-07** | 官方法律來源無法取得案例 | 來源驗證標記（UNAVAILABLE） | 嚴禁模型腦補假案號，明確標註未查證待補 |
| **TC-08** | 條陳公文字數或段落超限案例 | 格式驗證器阻擋與具體錯誤報告 | 攔截未達標公文，禁止核准輸出正式文件 |
| **TC-09** | 上游事實異動級聯失效案例 | 依賴下游審核記錄轉 STALE | 修改 G1 事實後，G2～G5 舊核准自動降為失效 |
| **TC-10** | 模型連線逾時或錯誤輸出案例 | 安全降級與錯誤保護 | 捕捉例外，自動切換本地離線法理規則引擎 |
