- **文件版本**：2.0
- **日期**：2026-10-27
- **修訂依據**：P1（8.4 分階段開發計畫與 9.2 條部署授權界線）

---

## 一、部署實施核心原則

1. **未經授權零變更**：未經使用者明確同意，嚴禁擅自建立雲端服務、修改 Render 設定、推送至 GitHub 或建立 Supabase 專案。
2. **階段門檻控制 (Gate Gating)**：每個階段必須完成所有前置條件驗收後，始得推進至下一階段。
3. **部署與驗收分離**：服務部署成功僅代表網路連線通暢，不等於系統品質驗收合格；部署後必須獨立執行完整迴歸測試。

## 二、分階段實施計畫 (P0 至 P9 路線圖)

| 階段代號 | 階段名稱 | 核心任務交付內容 | 必要驗收條件 |
| :--- | :--- | :--- | :--- |
| **P0** | **規格確認** | 確定 10 項未決清單（D-01～D-10），完成規格修訂書 v2.0 | 規格無未定模糊條款，原則經使用者認可 |
| **P1** | **本機應用骨架** | 建構前端對話研析介面、狀態機模型與本地離線規則引擎 | 本機服務順暢啟動、健康檢查通過、靜態檢查 0 錯誤 |
| **P2** | **認證與資料層** | 實作指定單一帳號登入、20 張資料表 Migration 與 RLS 政策 | 暴力破解防禦有效、無授權存取攔截通過、外鍵約束完備 |
| **P3** | **案件與事實流程** | 實作 Gate 0～Gate 1 案情建置、事實拆解與語意標註 | 原始案情不可變快照、五種陳述狀態正確區分 |
| **P4** | **法律分析與問句** | 實作 Gate 2～Gate 4 多重候選罪名評估與 9 大類問句生成 | 候選完整性達標、未知事實保留、問句與要件精準對應 |
| **P5** | **文件與條陳** | 實作 Gate 5 條陳公文模板、民國紀年、字數與段落驗證 | 格式驗證器無誤、支援 Word (.doc) 與文字檔匯出 |
| **P6** | **安全及復原** | 實作 AES-256-GCM 應用層加密、外部 AI 安全閘門與備份演練 | 竄改密文拒絕解密、隔離環境資料還原驗證通過 |
| **P7** | **部署前稽核** | 執行十大固定測試案例，產製四態稽核報告 | 所有必要項目均有 PASS 證據，無任何偽造項目 |
| **P8** | **雲端部署** | 經使用者明確授權後，依序配置 Render 服務與 Supabase 資料庫 | 服務健康檢查 200 OK、環境變數與金鑰安全注入 |
| **P9** | **部署後驗收** | 執行端到端實境測試，驗證跨裝置相容性與資安防護 | 登入、事實研析、問句生成、條陳匯出全流程驗收合格 |

## 三、待決事項確認時間表 (D-01 至 D-10)

在進入相關開發階段前，必須依序向使用者確認下列待決項目：

* **進入 P5 前**：確認 D-01（條陳正式全文模板、斷行排版與字數規則）。
* **進入 P4 前**：確認 D-02（第一階段 LLM 供應商評估與月費用上限）、D-03（官方法律資料庫或 API 介接方式）、D-08（第一階段正式法律分析範圍與特定罪名優先度）。
* **進入 P2 前**：確認 D-04（案件卷證檔案儲存方案：物件儲存 S3 vs 資料庫）、D-10（是否保持單一公務員帳號或預留未來協作欄位）。
* **進入 P6 前**：確認 D-05（RPO / RTO 目標與歷史案件保存期限）、D-06（金鑰安全儲存方案）。
* **進入 P8 前**：確認 D-07（免費方案限制評估，如 Render 休眠延遲與 Supabase 暫停限制是否符合期望）、D-09（系統用途：正式公務辦案輔助或研究性評估）。
