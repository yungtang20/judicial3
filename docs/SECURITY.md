## 一、威脅模型與防禦矩陣 (Threat Model)

| 威脅型態 | 潛在衝擊 | 實作防護控制 |
| :--- | :--- | :--- |
| **未登入存取受保護 API** | 機敏案件資料外洩 | 伺服器端 Token 檢驗，受保護路由全面攔截未認證請求 |
| **水平越權偽造案件 ID** | 越權存取他人案件 | 資料庫 RLS 策略與後端案件擁有者雙重強制驗證 |
| **資料庫 RLS 政策失誤** | 跨案件資料外洩 | 部署前自動化 RLS 模擬測試與權限稽核腳本 |
| **帳號暴力破解密碼** | 公務帳號遭劫持 | 連續錯誤 5 次自動鎖定 15 分鐘，IP 存取頻率限制 |
| **API 金鑰與憑證外洩** | 外部資源遭盜用 | 原始碼與 Git 嚴禁寫入任何 Secret，使用環境變數與金鑰輪替 |
| **資料庫實體外洩** | 機敏人名與案情暴露 | 應用程式層信封加密（AES-256-GCM），金鑰與密文實體隔離 |
| **外部 AI 意外傳輸** | 司法偵查機密受損 | 集中式外部 AI 傳輸閘門，預設全面停用（`ALLOW_EXTERNAL_AI=false`） |
| **金鑰或備份遺失** | 資料永久無法解密或復原 | 金鑰分離冷備份，定期於隔離環境執行還原演練 |
| **提示詞注入 (Prompt Injection)** | 惡意繞過權限或偽造指令 | 將所有案情輸入視為不可信資料，嚴格限制模型工具調用權限 |

## 三、應用程式層加密與金鑰輪替規範 (7.3 條)

1. **對稱式認證加密**：採 `AES-256-GCM` 演算法，保證密文之機密性與不可竄改性（Integrity Tag）。
2. **金鑰實體隔離**：金鑰儲存於安全金鑰管理系統（KMS / 受控環境變數），嚴禁與密文存放於相同資料庫。
3. **版本識別與輪替**：密文標註金鑰版本識別碼（`key_version`），輪替後舊金鑰保留唯讀解密能力，直至舊資料全數重密遷移完畢。
4. **防竄改檢驗**：解密失敗時嚴禁退回明文輸出，立即發出安全警報並記錄稽核事件。

## 四、外部 AI 集中式安全閘門 (7.4 條)

```
[使用者輸入案情]
       ↓
[後端安全閘門 (External AI Gate)]
       ↓ 檢查 ALLOW_EXTERNAL_AI === true && KEY_VERIFIED ?
   ┌───┴───┐
   │ 否     │ 是
   ↓       ↓
[本地法理   [脫敏過濾處理]
 規則引擎]     ↓
         [受控傳輸至外部模型]
```

* **嚴格後端控制**：前端無權擅自繞過後端閘門設定。
* **靜默切換禁止**：主要模型連線失敗時，嚴禁自動轉傳未經審核之第三方供應商。

## 五、備份與復原規格（RPO / RTO 目標驗收）

* **RPO（Recovery Point Objective）**：可接受最大資料遺失區間為 24 小時以內。
* **RTO（Recovery Time Objective）**：系統中斷後目標復原時間為 2 小時以內。
* **隔離還原演練程序**：
  1. 產製測試備份快照。
  2. 於隔離沙盒環境執行還原。
  3. 驗證資料表總數（20 張）、外鍵完整性與 RLS 政策。
  4. 驗證歷史加密案件解密功能正常。
  5. 記錄復原耗時，不得直接在正式資料庫執行破壞性驗證。
