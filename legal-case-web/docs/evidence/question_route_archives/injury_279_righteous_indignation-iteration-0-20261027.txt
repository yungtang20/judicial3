## E. 問句方法

- C02至C07分開確認基礎傷害、當場性與義憤脈絡、死亡結果、關聯與證據；不以同一答案跨要件推定。
- C08只補普通傷害、重傷害、身分加重與程序路由的外部脈絡；任何單一答案都不產生 `ACTIVE` 或法律結論。
- 所有 `UNKNOWN`、`CONFLICT` 與替代方向維持 `NEED_REVIEW`。

## G. 角色實體化規則

- ID為 `<concept_id>-<V|S|T|W>`；`witness_review_only` 永遠 `runtime_enabled: false`。
- C01先問；C03、C04、C07只在既有 fact 為 `UNKNOWN` 或 `CONFLICT` 時追問。既有資料完整時只引用；衝突時保留新舊版本，不得靜默覆蓋。
- 刑事訴訟法第95條權利告知與既有筆錄為程序題，不納入八個 offense concepts。

## H. 回答效果與聚合

- 所有單題均不得產生 `ACTIVE` 或 `EXCLUDED`。
- `LOWERED` 只表示該軸較不支持某 route；多要件與相反資料仍由 Human Gate 聚合。
- 詐術、錯誤、財產處分、損害流向、不法所有意圖及行為進度均須由不同來源共同供人工評價；即使一致，本階段最高仍為 `CANDIDATE_NEED_REVIEW`。
- `UNKNOWN`、`CONFLICT` 及未列入 scope 的相鄰 route 全部為 `NEED_REVIEW`，不得直接排除。

## I. 去重與既有題處理

| concept | 既有來源 | 處理 |
|---|---|---|
| C01 | FRAUD-N-01 | 自由敘述重用，不共同出題 |
| C02-C07 | 無或跨 route 語意不等同 | 依缺漏／衝突追問，不共同出題 |
| C08 | 既有證據來源欄位 | 只補證據來源，不把資料存在等同要件成立 |

## J. 不採用問句

- 「你是不是騙人，所以構成詐欺？」：把法律結論塞入問題。
- 「你收錢後沒有履約，就是詐欺？」：把民事履約爭議直接等同詐術。
- 「對方已經付款，所以一定有錯誤及因果關係？」：單一結果不足。
- 「金額短少就是詐欺損害？」：未確認流向、原因與損害資料。

## K. 最低校準案例

| 案例 | 期望輸出 |
|---|---|
| 虛構投資獲利後收款 | C02-C06 均需外部資料；不得單題升ACTIVE |
| 真實交易但後續未履約 | 詐術、行為時意圖與民事爭議分開，最高 `CANDIDATE_NEED_REVIEW` |
| 對方誤解但未交付財物 | C03可保留；C04為 `NEED_REVIEW`，不得補推損害 |
| 有交付但損害與流向不明 | C05 `NEED_REVIEW`，不得由金額短少推定 |
| 僅有事後說法、無可核對資料 | C08 `NEED_REVIEW` |
| 僅開始實行但未取得財物 | C07保留外部進度；不直接作既遂／未遂結論 |
| 跨角色說法衝突 | 對應 fact 為 `CONFLICT`，全部 `NEED_REVIEW` |
